Abstract

Most state-of-the-art 3D point cloud backbones are hybrids that combine attention with sparse convolutions. While the convolutions supply local geometry, they add architectural complexity, hinder deployment, and tie the network to a discrete voxel grid. Convolution-free point transformers avoid these costs, yet they still trail the hybrids when trained on a single dataset with matched supervision.

Dropping the convolutions frees the network from the voxel grid, but we hypothesize that current convolution-free backbones do not fully exploit the continuous point geometry. Pooling the points onto voxels discards their sub-voxel positions, and in attention, positions only influence where a query attends, while the values it aggregates carry no information about where they come from. We address both with operators built on phasors of the continuous point coordinates. Phasor pooling embeds each token from the exact positions of its points, and phasor attention makes the values geometry-aware while staying compatible with efficient attention kernels.

Building on both, PhasorPT is a convolution-free point transformer that operates on continuous coordinates throughout. It matches or exceeds the hybrid PTv3 on multiple indoor and outdoor datasets with half its parameters and without a single convolution. With additional supervision from a convolutional teacher trained on the same data, it surpasses all baselines on ScanNet, ScanNet200, and SemanticKITTI.

Two places where geometry gets lost

Both fixes use one encoding: a phasor, a plane wave evaluated at the exact point position.

Tokens

Voxel patch embeddings forget where the points lie inside a cell.

Phasor pooling embeds each token from the exact offsets of its points.

 Attention

With RoPE, the values do not know where they come from.

Phasor attention rotates the values by their positions, so the output knows where the attention landed.
Operator 1

Phasor pooling

Every point samples a few learned plane waves at its offset from the token centroid. Averaging features times waves gives a fixed-size token, whatever the number of points, with a kernel that is smooth in the exact position.

Operator 2

Phasor attention

RoPE rotates queries and keys: it decides where a query attends. Phasor attention also rotates the values by their positions (amber), and the output back by the query position.

Each value then enters the output relative to the query. The output's phase tells where the attention landed, its length how spread out it was.

Both rotations sit outside the attention, so FlashAttention runs unchanged.

The query at the centre aims its attention (amber cross). Gray patches hold no points, so attention aimed there lands on the surrounding points instead.

Each dial is the output of one frequency, below for x, right for y. The tick shows where it would point if the attention had landed at the aim.

Phasor attention: on a miss the arrows turn away from their ticks and shrink, so the output shows where the attention actually went. RoPE: every arrow points right, whatever happens.

Value content: mixes a feature into each value (black strokes on the keys). The output then carries content and geometry together; at 0 it shows the geometry alone.

PhasorPT

Phasor pooling turns the points into tokens, serialized phasor attention blocks run on a fine local and a coarse global stream, and phasor unpooling maps back to the points. No convolutions anywhere.

Run PhasorPT in your browser

Without sparse convolutions, PhasorPT is easy to deploy: ported to Rust with Burn, it runs locally in your browser via WebAssembly and WebGPU, no server needed. The model is the ScanNet one from the main table (CNN teacher, 78.3 mIoU).
